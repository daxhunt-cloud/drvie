### 권장안: Option A (PostgreSQL DB 트리거)

**이유**: 즉각 적용 가능하고 클라이언트 코드 변경 없이 모든 INSERT/UPDATE 경로를 방어한다. Map.tsx는 이미 2379줄 메가 컴포넌트로 대규모 리팩터 리스크가 높다. Option B의 API Route 분리는 T-001 별도 아키텍처 티켓(Map.tsx 분리, 감사 항목 A-1)과 연계해 P1 스프린트에서 병행 진행이 적합하다.

**신규 파일**: `scripts/text-filter-trigger.sql`

```sql
-- 금칙어 정규화 함수 (text-filter.ts의 normalize() 로직 이식)
CREATE OR REPLACE FUNCTION normalize_for_filter(input TEXT)
RETURNS TEXT
LANGUAGE plpgsql IMMUTABLE AS $$
BEGIN
  RETURN regexp_replace(
    regexp_replace(
      regexp_replace(
        regexp_replace(
          regexp_replace(lower(input),
            '[\s\-_.!@#$%^&*()=+~|\\/<>?,;:''"''\[\]{}]', '', 'g'),
          '0', 'o', 'g'),
        '1', 'i', 'g'),
      '3', 'e', 'g'),
    '4', 'a', 'g');
END;
$$;

-- 금칙어 검사 함수 (BANNED_WORDS 배열: text-filter.ts와 동기화 유지)
CREATE OR REPLACE FUNCTION contains_banned_word(input TEXT)
RETURNS BOOLEAN
LANGUAGE plpgsql IMMUTABLE AS $$
DECLARE
  banned TEXT[] := ARRAY[
    '시발','씨발','시bal','씨bal','ㅅㅂ','ㅆㅂ','시바','씨바',
    '개새끼','개새기','개색끼','개색기','개세끼','ㄱㅅㄲ',
    '병신','ㅂㅅ','병시','byungsin',
    '지랄','ㅈㄹ','지럴',
    '좆','좃','ㅈㅇ',
    '니미','니엄마','느금마','느금','니애미',
    '미친놈','미친년','미친새끼','ㅁㅊ',
    '꺼져','닥쳐','죽어',
    '걸레','창녀','창남',
    '씹','ㅆ','보지','자지',
    '새끼','색끼','ㅅㄲ',
    '엿먹어','엿먹',
    '개같은','개년','개놈',
    '후장','항문','성기','음경','음부',
    '강간','성폭행','자살','자해',
    '시1발','씨1발','s발','si발',
    'ㅂ ㅅ','ㅅ ㅂ','ㅈ ㄹ',
    'fuck','fck','fuk','f*ck',
    'shit','sh1t','s hit',
    'bitch','b1tch','asshole','ass hole',
    'dick','d1ck','pussy','pus5y',
    'nigger','nigga','bastard','whore','slut','porn','hentai'
  ];
  word TEXT;
  normalized_input TEXT := normalize_for_filter(input);
BEGIN
  FOREACH word IN ARRAY banned LOOP
    IF position(normalize_for_filter(word) IN normalized_input) > 0 THEN
      RETURN TRUE;
    END IF;
  END LOOP;
  RETURN FALSE;
END;
$$;

-- 트리거 함수
CREATE OR REPLACE FUNCTION enforce_text_filter()
RETURNS TRIGGER
LANGUAGE plpgsql
SECURITY DEFINER AS $$
BEGIN
  IF contains_banned_word(NEW.title) THEN
    RAISE EXCEPTION 'BANNED_WORD_IN_TITLE' USING errcode = 'P0002';
  END IF;
  IF NEW.description IS NOT NULL AND contains_banned_word(NEW.description) THEN
    RAISE EXCEPTION 'BANNED_WORD_IN_DESCRIPTION' USING errcode = 'P0002';
  END IF;
  RETURN NEW;
END;
$$;

-- 트리거 등록 (BEFORE INSERT OR UPDATE)
DROP TRIGGER IF EXISTS enforce_text_filter ON courses;
CREATE TRIGGER enforce_text_filter
  BEFORE INSERT OR UPDATE OF title, description ON courses
  FOR EACH ROW EXECUTE FUNCTION enforce_text_filter();
```

### Scope Extension (2026-05-26 · post-spec amendment)

PO 검증 과정에서 `src/lib/text-filter.ts`의 `containsBannedWord`가 최초 spec에 기재된 `Map.tsx` 외에 **2개 추가 호출 사이트**에서도 사용 중임이 확인됐다: `src/components/CourseComments.tsx`(댓글 `comments.text` 제출 시) 및 `src/app/(main)/settings/page.tsx`(프로필 닉네임 `profiles.nickname` 저장 시). 두 경로도 동일한 E-1 우회 리스크에 노출돼 있었으므로 트리거 보호 범위를 확장해 함께 반영됐다.

**최종 배포 트리거 구성** (3개, `normalize_for_filter` + `contains_banned_word` 헬퍼 공유):

| 트리거명 | 테이블 | 보호 컬럼 | 예외 코드 |
|---|---|---|---|
| `enforce_text_filter` | `courses` | `title`, `description` | `BANNED_WORD_IN_TITLE` / `BANNED_WORD_IN_DESCRIPTION` |
| `enforce_comment_filter` | `comments` | `text` | `BANNED_WORD_IN_COMMENT` |
| `enforce_profile_filter` | `profiles` | `nickname` | `BANNED_WORD_IN_NICKNAME` |

**기술 수정 사항**: 원본 spec의 정규식 문자 클래스 `'[\s\-_.!@#$%^&*()=+~|\\/<>?,;:''"''\[\]{}]'`가 Supabase SQL Editor에서 `END IF` 부근 구문 오류를 발생시켰다. 따라서 더 단순한 화이트리스트 부정 패턴 `'[^a-z0-9가-힣ㄱ-ㅎㅏ-ㅣ]'`으로 교체했다. 아울러 달러 인용 구분자도 `$$`에서 `$func$` 태그 형식으로 변경해 중첩 충돌을 방지했다.

**Supabase 검증** (2026-05-26 적용 완료): `information_schema.triggers` 조회 결과 6행(트리거 3개 × INSERT/UPDATE 각 1개) 확인. `contains_banned_word` 스모크 테스트 통과.

## Notes / risks

- **롤백**: 트리거 삭제 SQL 1개로 즉시 복구 가능 (`DROP TRIGGER enforce_text_filter ON courses; DROP FUNCTION enforce_text_filter; DROP FUNCTION contains_banned_word; DROP FUNCTION normalize_for_filter;`)
- **성능**: `BEFORE INSERT OR UPDATE` 트리거는 `enforce_course_limit` 트리거와 동일 시점에 실행. 두 트리거가 순서대로 실행(PostgreSQL 알파벳순 기본)되어 서로 영향 없음.
- **이원화 리스크**: `text-filter.ts` 수정 시 SQL도 반드시 함께 수정. PR 체크리스트에 명시 필요.
- **`IMMUTABLE` 주의**: `contains_banned_word`를 `IMMUTABLE`로 선언했으나 배열이 함수 본체에 있어 실질적으로 문제 없음. 별도 테이블 참조 시에는 `STABLE`로 변경 필요.
- **Audit miss 기록**: Designer 원본 spec은 `Map.tsx` 한 곳만 점검했으나 PO 검증 단계에서 `CourseComments.tsx`, `settings/page.tsx` 2개 추가 호출 사이트가 발견됐다. 향후 보안 강화 대상 유틸리티 수정 시 **해당 유틸의 모든 import 사이트를 grep으로 전수 확인** 후 영향 범위를 spec에 명시할 것.
